# PhotoPlay - agent guide

Read this before touching code. Users read [README.md](README.md). This repository is an ai-space app; the contract is ai-space `docs/app-spec.md` (spec 1) and `space.yaml` is the only file ai-space reads.

## Rules

1. **Be honest.** Data you cannot obtain stays empty or is marked missing; `/api/widget` returns `{ ok: false, error }` on failure and the panel shows it as is.
2. **Traceable.** Every record answers "where from, when".
3. **Append, never rewrite.** History is added to, not edited.
4. **Configuration is environment.** Real values live in `.env` (ignored) or in the `space.env` ai-space generates; the repository holds only `.env.example`.
5. **Loopback only.** The service binds `127.0.0.1:${PORT}`; exposure is the space's job.
6. **Portable.** Skills and prompts name no host, ssh alias or home directory and carry no "am I on the server" marker; they take paths from the environment (`SPACE_APP_DIR`, `SPACE_APP_DATA_DIR`, `DATABASE_URL`) and the machine from the workspace `AGENTS.md`. Deployment facts live in the Deployment section below and nowhere else.

## Stack and runtime model

- Bun + TypeScript, no framework, no runtime dependency. `src/index.ts` boots the service (`Bun.serve` with the HTML import of `web/index.html`), `bun:sqlite` for metadata, image files in the blob store (`BLOB_URL`, `file://` only).
- Pictures come only from ai-space: `src/model.ts` calls `POST ${SPACE_API_URL}/api/model/image` with `SPACE_APP_TOKEN`, tag = template id. Never add an image API key or spawn a CLI here; if the space lacks an operation, extend ai-space.
- Jobs: `POST /api/jobs` creates one per idempotency key (`key`, generated by the page per submit), `src/worker.ts` runs them one at a time, oldest first. A job left `running` by a restart becomes `unknown` on boot and is never retried automatically: the model call may have been spent. Retry is by hand (`POST /api/jobs/:id/retry`, a new job).
- Versions: a job's `baseId` is the original or its parent job's result; assets are stored once per SHA-256, and deleting an artwork removes only files nothing else refers to.
- Templates (`src/templates.ts`) are versioned; `overlay: true` parameters (titles, places, dates) never reach the model and are drawn by the page (`drawOverlay` in `web/overlay.ts`), editable later via `PATCH /api/jobs/:id/overlay`.
- Uploads: the page re-encodes to JPEG at most 2048 px (drops EXIF, stays under the model service's 5 MB); the server checks the bytes and strips EXIF again. Thumbnails are made by the page and `PUT /api/assets/:id/thumb`: the service has no image library.

## Conventions

- Page routes trust loopback (the edge holds the login); the page never holds a token.
- Widget contract: `GET /api/widget` -> `{ ok: true, items: [{ text, url, time }], asOf, staleAfter, blocks }` (`src/widget.ts`): items newest first, at most twenty, kept for older panels; blocks are the state card (latest work, queue, retries, versions per day, totals).
- Tests sit next to the code, use `:memory:` databases and a stand-in generator; no network, no model.
- English in code, comments, docs and commits.
- The page follows ai-space docs/app-spec.md#app-pages: full-bleed (the side and the view reach the edges, split by 1px rules), Chinese and English, a system / light / dark theme button. A new visible string is a key in both dictionaries of `web/i18n.ts`; a template's words are `{ zh, en }` in `src/templates.ts`. The API never returns page text: a refusal is `{ ok: false, code, params, error }` and the page translates `error.<code>`; `/api/status` gives `reason` as a code. Job errors come from ai-space or the model and are shown as they are. The manifest's `url: /?lang={lang}` passes the panel's language; the choice is kept under `photo-play.lang` / `photo-play.theme`.
- The icon (`icon.svg`, the space's generated per-app icon embedded as WebP) is served at `/icon.svg` and used as the page's logo and favicon.

## Deployment

- Runs on the space host as an ai-space supervised service (`space-photo-play.service`, user level), port 8975; `space app service photo-play`, `space app restart photo-play`, logs `journalctl --user -u space-photo-play -f`.
- Deploy: `git push deploy main` to the bare repository `<workspace>/repos/photo-play.git` on that host; its `post-receive` hook (`deploy/post-receive`) runs `space app deploy photo-play`: checkout, `bun install --frozen-lockfile`, `deploy.check`, restart, wait for `/healthz`; a failure keeps the previous tree and service. A new app's first deploy also needs `space app sync` on that host.
- Public URL: the space router's wildcard hostname `photo-play.<SPACE_DOMAIN>`, behind the space's access layer.
- Pictures need a `codex` runtime on the space (the only kind that makes images); `model.default: codex/intermediate` pins it, because a space's default runtime may be one that makes no images.
- Source: GitHub `ericz-lab/photo-play` (public, MIT, remote `origin`). After a deploy, `git push origin main`.
- App store: `space.release.yaml` (spec 2) is the package; it must carry `space.yaml`'s components minus `service`/`url`/`deploy` (`src/release.test.ts`). To release: raise `version` there and in `package.json`, commit, tag `v<version>`, push the tag; `.github/workflows/release.yml` builds `dist/` (`bun run build`: the service with the page and the sample pictures), packs `dist` and `icon.svg`, signs with the `SPACE_SIGN_KEY` secret and attaches the `.spaceapp` files to the GitHub release. Then the catalog (`ericz-lab/ai-space-apps`) lists the new version. `bun run pack` (with `SPACE_CLI` pointing at an ai-space that has `app release`) builds the same packages locally.
- The bundle finds the page's files from the working directory, so `src/index.ts` changes into `dist/` when it runs bundled; never use `new URL(..., import.meta.url).pathname` (breaks on Windows).
- Keep `bun.lock` at `"lockfileVersion": 1` while a host runs Bun 1.3.

## Usage measurement

App pages load `/_space/usage.js` at runtime through the Space router. It records visible, recently active time without page content or credentials. Refresh existing tabs after deployment; earlier unmeasured time cannot be recovered. Direct-port access has no Space heartbeat endpoint. `usage.test.ts` checks every application page loader; run it with `bun test usage.test.ts`.
